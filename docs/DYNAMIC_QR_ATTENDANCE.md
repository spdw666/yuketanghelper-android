**雨课堂动态二维码签到：公开资料核实**

> 历史范围：以下核实针对 0.2.4 及当时的公开源码。自 0.2.5 起已修正进课堂后的成功提示，动态二维码签到仍未实现。当前实现与验证见 [0.2.6 记录](VALIDATION-0.2.6.md)。

核实日期：2026-10-19（北京时间）。本次只读取公开网页、官方帮助内容和 GitHub 源码，没有登录真实账号、调用课堂签到接口或进行猜码测试。App 和 APK 未作修改。

**核实结论**

1. 雨课堂有专门的动态二维码签到模式，与普通进入课堂存在区别。官方明确说明，开启该模式后，通过其他进班渠道进入的学生仍会被教师端记为未签到。
2. 当前 Kotlin App 继承上游的课堂接入逻辑，以获得 `lessonToken` 作为“课堂签到成功”的依据。这个结果不足以证明完成动态二维码考勤。
3. 在本次检查的官方帮助中心及公开入口中，没有找到面向第三方开发者的动态签到 API 规范。没有获得可验证的请求参数、动态凭据有效性规则、考勤状态响应字段和接入授权说明。这个结论仅适用于本次查询范围，不表示官方内部或校方合作渠道不存在接口。
4. 公开项目中，普通“自动签到”的描述不能作为支持动态二维码的证明。一个较活跃的参考项目明确声明不支持动态二维码；另有项目将相关内容标为测试，未提供足以证实动态考勤完成的官方依据。

**官方证据**

[《如何在上课签到时开启动态二维码》](https://www.yuketang.cn/help?detail=501)，官方帮助条目 501，页面记录创建于 2025-02-11，本次已在线读取全文。可复核的[官方内容响应](https://www.yuketang.cn/c27/online_courseware/help_center/questions/501)。

该条目说明：

- 该功能当时仅支持校内班级，个人自建班级暂未支持。
- 教师需安装 V6.2.2 及以上版本插件。
- “签到界面开始8秒倒计时，倒计时结束后会重新生成二维码”。超时需重新扫码。
- **“开启时，学生通过其他进班渠道，均无法完成签到，教师端记为未签到。”**

上述版本要求和刷新说明是该条目记载的产品行为，不推断为所有部署版本永远不变的协议常量，也不能据此推导动态凭据算法。

[《雨课堂是如何实现考勤签到的？》](https://www.yuketang.cn/help?detail=23)，官方帮助条目 23，本次已读取全文。该文列出扫码、课堂暗号、“正在上课”提示等进课堂方式，并说明教师可通过课中名单和课后课堂小结查看考勤。导出数据分别记录“签到方式”和“是否上课”。结合动态签到专门条目，进入课堂与动态考勤通过应分别判断。

[官方帮助中心](https://www.yuketang.cn/help)的公开搜索已查询“动态”“签到”“API”“接口”。“动态”和“签到”返回上述产品帮助；“API”无结果，“接口”返回 WPS 试卷制作授权相关说明，没有动态签到开发规范。另检查官网、登录入口、下载页以及网页搜索结果，仍未发现可确认的官方第三方动态签到 API 文档。网页搜索结果有不相关内容，未将其作为技术事实证据。

**对当前 App 的影响**

当前代码 `MonitorEngine.kt` 在 `gateway.checkIn()` 返回后直接显示“课堂签到成功”；`YuketangApi.kt` 的返回条件是收到课堂连接凭据。该文案可能让动态签到用户误以为已经完成考勤。合理的改法是先显示“已进入课堂；考勤状态待确认”，只有取得独立、明确的考勤结果后才显示签到成功。

实现动态二维码识别时，应使用现场实际获得的有效二维码，并在合法接入流程中确认服务器考勤结果。仅有二维码刷新间隔和课堂编号，无法确认动态凭据内容或算法；现有资料也不足以保证只改请求参数就能支持。下一步需要官方或校方提供的接入规范，或者在用户本人正常扫码过程中、凭据留在本机的情况下核对成功与失败的考勤返回。过期、拒绝和状态不明都不应显示成功。

本次交付的是资料核实结果，尚未实现或验证动态二维码签到。
